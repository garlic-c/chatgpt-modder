# 官方更新后旧备份阻止重新应用

日期：2026-10-30。修复版本：0.1.0-preview.12。

## 现象与证据

ChatGPT 从 26.1023.51421 更新为 26.1027.30824 后，修改器能识别新版本，但应用时提示：

> 客户端发生变化，拒绝覆盖或旧版恢复

只读检查确认：客户端路径没有改变；现有备份清单的 version 仍为 26.1023.51421，installedTree=null、modules=[]，属于已恢复原版后保留的记录。旧备份本身与其 originalTree 一致，当前新客户端也通过了新适配器的资源和原生指纹检查。

这次故障不是通过删备份、改权限或关闭校验解决的。

## 根因

原备份状态仅按客户端根路径保存，没有区分更新前后的版本。inspect() 在旧记录 installedTree=null 时允许新原版通过适配检查；apply() 却继续用旧清单的 originalTree 比较新客户端，因而拒绝。

新增新版适配器只解决了资源识别，没有处理现存安装状态的升级衔接。此前真实副本测试主要使用独立的新备份目录，遗漏了“同一路径 + 旧清单 + 新原版”的组合。旧版已安装补丁与旧版已恢复两种状态都必须覆盖。

## 解决方式

1. 发现旧清单与当前客户端版本不同后，先验证当前客户端是严格匹配的已知原版：版本、非空且精确匹配的 ASAR 头、界面资源及已声明的原生文件指纹都必须通过。
2. 用户明确重新应用且客户端完全退出后，创建独立备份状态。旧清单、旧原版备份和已存在的历史状态保留不动，不把旧补丁或旧模块选择自动套到新版本。
3. 根路径的 operation.lock 保持固定，所有备份状态共用这把锁；不能因切换状态而释放互斥。
4. active.json 以原子写入选择 generations/〈随机指纹〉/ 内的新状态。无 active.json 时兼容旧布局。新状态记录中断时，只处理当前状态的暂存资源，旧备份不受影响。
5. 恢复显式检查版本，并且只能使用当前状态对应的新原版备份。即使目录字节恰好相同，版本不同也拒绝恢复。
6. 同版本的异常变化、未知版本、指纹不匹配和未完成的事务继续拒绝；没有放宽原有校验。

实现入口：src/engine/engine.ts 的 loadGeneration、startGeneration、inspect、apply、withLock、restore 和 recover。

## 验证

修复提交：00a9df885d8f41612e9a8039777d25cb26298fe2。

- 51 项本机自动化测试通过；两平台 CI 构建与发行通过。
- 使用真实新 Mac 客户端的隔离副本及复制的旧清单，完成版本切换、应用、恢复；恢复后全目录与新原版完全一致。
- 实际旧备份仅被只读引用，真实旧清单未改变，官方安装和账号资料未改动。
- 已发布并在本机安装 preview.12。上述证据是自动化与隔离回归结果，不冒充用户再次试运行的反馈。

新增回归位于 tests/engine.test.ts：

- 已知官方更新建立独立备份，保留已安装的旧版记录。
- 已知官方更新建立独立备份，保留已恢复的旧版记录。
- 未知更新不得切换备份代际。
- 同版本非 ASAR 文件变化仍拒绝，不误判为官方更新。
- 新代际准备中断可恢复，旧代际和目录外文件不受影响。
- 版本变化时即使目录字节一致也不能恢复旧版。

正向用例还覆盖重新打开修改器后读取当前状态、重复应用，以及恢复新版而非旧版。

## 后续版本的必做检查

每次适配官方更新，先检查现有清单与当前客户端版本，不能只在空备份目录中验证成功就发布。至少完成下列矩阵：

| 现有状态 | 当前客户端 | 预期 |
| --- | --- | --- |
| 无记录 | 已知原版 | 新建备份、应用、恢复 |
| 旧版补丁已安装 | 已知新版原件 | 旧记录保留，新版独立备份，恢复只回新版 |
| 旧版已恢复但记录保留 | 已知新版原件 | 同上；不能被旧 originalTree 阻挡 |
| 任一旧状态 | 未知或指纹不符的新版 | 拒绝，不改变现有记录或客户端 |
| 当前版本记录 | 同版本文件异常变化 | 拒绝，不误判为官方更新 |
| 新状态准备中断 | 原客户端未改变 | 可恢复暂存，不影响旧记录 |

此外检查状态切换后仍共用稳定操作锁、重启能读取 active.json、路径记录不能越界，以及旧备份不能跨版本覆盖。

禁止用删除 manifest.json、installed.json、original.app 或放宽 treeHash 来绕过冲突。若新版本仍失败，保留现场，先区分未知版本、资源变化、记录版本不符和事务中断。
