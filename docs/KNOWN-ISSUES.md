## WIN-003：用户应用修改后重启 ChatGPT 没有效果

- 状态：开放；阻塞 Windows 普通使用验收。
- 用户反馈：应用修改后重启 ChatGPT 没有效果。
- 已确认：修改器记录的用户目录副本为 26.1027.30824，ASAR 中存在新组件、原组件包装和固定额度绑定；副本 PE 的 ASAR 头声明与归档一致。桌面 ChatGPT（Modder）快捷方式指向该副本。
- 尚未确认：该次重启使用的入口、实际运行程序路径、默认资料目录及单实例/包激活行为。检查时没有运行中的 ChatGPT，不能追溯那次窗口的实际来源。
- 不得结论：不能断言用户开错入口，不能说是权限问题，也不能用隔离测试成功认定此反馈已解决。
- 后续：复现普通快捷方式端到端启动，核对副本程序路径、版本、补丁状态和运行实例；再排查配置路径、登录状态、初始化与模块渲染。禁止改写官方 WindowsApps 作为兜底。

隔离调试副本使用新建配置目录，正式 Modder 快捷方式没有同样的配置选项。这两条路径的证据必须分开。

## WIN-002：26.1027.30824 已实验适配，完整使用流程尚未验收

- 商店包版本 26.1027.3384.0 与 ASAR 版本 26.1027.30824 不同，记录时不能混用。
- preview.10 已固定整个 ASAR 头、primary/initial/shared 三份资源 SHA256，以及头像组件和账号/查询绑定，状态仍为 experimental。
- 已通过：真实独立副本的准备、应用、重复应用、原样恢复与重新启用；运行中拒绝修改；隔离副本用户手动登录、真实额度、头像对齐、侧栏切换和主题 CSS 样式。
- 未全面验收：普通快捷方式重启（见 WIN-003）、所有登录回调、默认资料目录与单实例行为、真实切号/休眠唤醒、持久主题设置和商店升级维护。
- 副本不随商店更新；未知版本和文件指纹不符仍必须拒绝修改。不得将适配器改为 verified 或描述为 Windows 全流程可用。

详见 [preview.10 证据](WINDOWS-preview.10.md)。

## WIN-001：preview.8 自动定位失败

- 状态：preview.9 在本机复现并修复；后续机器仍需独立验证。
- 根因证据：PowerShell 成功找到包和主程序目录，但实机 PE 资源使用大写 SHA256 与双反斜杠路径，旧解析器拒绝；发现层吞掉异常，最终返回 null。
- 修复：兼容实机资源格式，仍检查唯一条目、SHA256、有效哈希和 PE/ASAR 一致性；记录包查询、清单、候选来源与失败阶段，清单路径检查失败保留已定位结果。未定位也能导出诊断。
- 不能推论：定位成功不等于版本支持、补丁成功或日常启动成功。
