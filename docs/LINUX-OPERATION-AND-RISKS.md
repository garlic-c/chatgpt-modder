# Linux 运作原理与风险

> 官方 Release 暂不提供 Linux 发行包：ChatGPT 的 Linux 客户端界面布局与 macOS/Windows 不同，额度显示效果未经真机确认。本文供从源码自行改造编译的用户参考。

官方 `.deb` 把客户端安装到系统目录 `/usr/lib/chatgpt`，普通用户无写权限。修改器不直接改动系统安装，而是采用与 Windows 商店版相同的策略：先在用户目录建立一份完整副本，之后所有应用、恢复都只作用于这份副本。

## 副本与启动

- 副本位于修改器数据目录的 `clients/` 下，按官方安装的路径和 ASAR 指纹分开存放；官方版本变化会生成新副本，旧副本保留。
- 应用成功后，修改器在 `~/.local/share/applications/chatgpt-modder.desktop` 写入启动项 **ChatGPT（Modder）**。请从这个启动项打开修改版；官方的 `chatgpt` 命令与系统启动项保持原样，仍打开官方版。
- 副本是独立程序目录，官方 `.deb` 升级不会同步到副本；官方版本更新后需重新应用，修改器会校验新版本指纹并为新版建立独立备份（流程与 macOS/Windows 的升级衔接一致）。
- 副本可能需要重新登录。修改器不读取、不复制官方安装或副本中的账号凭据、Cookie 或聊天数据。

## 完整性模型

Linux 版客户端不在主程序中声明 ASAR 头哈希（无 Info.plist、PE 资源或框架摘要槽）。修改器以适配器记录的 ASAR 头哈希、界面资源哈希和主程序 `ChatGPT` 的哈希识别官方版本；重写归档后逐项校验归档内每个文件的完整性条目（含 `app.asar.unpacked/` 中的原生文件），确保归档自洽。未知版本或指纹不符时拒绝修改。

## 已知注意事项

- 客户端每次启动都会在自身安装目录下创建一个空的 `extensions/` 目录（官方原版同样如此）。该目录出现后，修改器的全目录指纹会变化，恢复操作会按安全规则拒绝。若需要恢复，请先完全退出 ChatGPT，再删除副本根目录下这个空的 `extensions/` 文件夹，然后执行恢复。
- Linux 适配目前为实验状态：指纹与组件绑定取自官方 `.deb` 资源逐项核对，引擎流程已用真实客户端副本在 Ubuntu 24.04 完整验证（应用、完整性校验、启动、原样恢复），但登录状态下额度组件的实际显示尚未经用户确认。
- AppImage 未签名；部分发行版需要安装 FUSE 才能直接运行 AppImage，或使用 `--appimage-extract-and-run`。
