# 扩展开发

## 组成

- `src/main.ts`：Electron 主进程，提供窄范围的文件选择、诊断、安装、恢复接口；只接受主窗口来源。
- `src/engine/`：平台识别、进程检查、ASAR 流式重写、Mac 框架摘要和签名、Windows PE 完整性资源、备份及事务恢复。
- `src/modules/`：仅随程序发布的内置模块和已知版本适配记录。
- `src/ui/`：功能选择与预览。首个额度模块有专用示意图；后续注册模块自动得到基础开关卡片。

预加载桥启用上下文隔离和沙箱；界面无 Node.js 权限，不加载远端页面、脚本或功能包。界面 CSP 禁止网络连接，主进程没有遥测或上传功能。

## 增加模块

实现 `FeatureModule`：提供 id、版本、名称、描述、依赖、冲突和归档内的修改目标，以及 `prepare()` 和 `verify()`。在 `builtInModules` 注册，并为适用的客户端版本增加明确的资源指纹。

`prepare()` 接受从原始备份读取的文本文件集合，返回修改前后的内容；不得写文件、读取账号凭据或启动后台进程。`verify()` 检查最终资源中的模块标识及必要锚点。模块的移除通过从原版重新构建剩余模块完成，不依赖脆弱的反向字符串替换。

依赖必须显式选择，按依赖顺序准备。循环依赖、未知模块、重复模块、声明冲突及多个模块修改同一文件都会在写入之前拒绝。当前不支持共享文件编辑的自动合并；需要先设计明确的共享适配层，再改变这一约束。

新增模块默认关闭。加入模块注册后，主进程自动提供元信息，界面生成基础功能开关；可再增加专用预览。所有选中模块先统一验证，随后一次提交。

## 版本适配

Mac 适配器固定版本、ASAR 文件头哈希、共享界面文件哈希及关键原生组件哈希。Windows 实验适配固定版本和同构建的共享界面文件哈希，并验证 PE 内的 ASAR 哈希与归档一致；由于没有从目标 Windows 包取得整体归档指纹，其适配始终标为实验，不能标记已验证。

额度模块中的短变量名和组件锚点仅适用于已记录构建。不要用跨版本猜测替代适配。诊断导出只包含版本、文件名及资源哈希，不包含运行时账号、聊天或凭据。

## 写入事务

1. 取得按客户端规范路径区分的操作锁，检查版本、指纹及进程。
2. 全目录备份并核对内容指纹；符号链接保留原始相对目标。
3. 写入 `preparing` 事务，复制原版为相邻暂存应用，从原版一次构建选中模块。
4. 更新平台完整性资源，完成平台验证；Mac 先签辅助进程，再签框架和主程序。
5. 再检查客户端未启动、内容未改变；记录 `staged` 和最终目录指纹。
6. 记录 `swapping`，将当前目录改名保留，再将暂存目录放到目标位置。
7. 写入新状态并记录 `committed`，最后清理上一个目录与事务。

正常失败自动回滚；异常退出后可按日志恢复。锁文件记录进程号，活跃操作不能抢锁。已经被升级或外部修改的目录、损坏的备份或回滚副本均拒绝覆盖，保留现场。恢复副本同样使用准备、校验与原子替换流程。

备份内容指纹覆盖文件名、内容、权限位和符号链接；不承诺还原文件系统 ACL 或所有扩展属性。Mac 处理签名时只清理 FinderInfo 和 ResourceFork 两类签名不兼容的属性，不修改系统整体安全设置。

## 不常驻约束

修改器没有托盘、启动项、定时后台任务或额外额度服务。关闭最后窗口调用 `app.quit()`，包含 macOS。写入事务进行中阻止退出；完成后可立即关闭。

注入的额度代码作为 ChatGPT 页面组件运行，复用其 React、当前账号及额度状态；事件和计时器在卸载时清理。组件发生故障时由边界隔离，保留原头像组件。该模块不向全局对象暴露凭据，也不建立监听端口。

## Windows 发现与副本原型（当前状态）

preview.8 的 `discovery.ts` 使用当前用户商店包及清单路径；`main.ts` 包装受保护安装检查，拟由 `windows-copy.ts` 创建用户目录副本后交给同一引擎修改。此发现流程在用户 Windows 实机仍失败，副本路径尚未实机验收。`docs/HANDOFF-WINDOWS.md` 是继续开发的当前入口。

注意：UI 当前固定一个额度开关与专用预览。内置模块接口可扩展，但新增模块的完整 UI 需要修改 `src/ui/`；本文较早的“自动得到基础开关卡片”描述并非当前完整实现能力。

## 已知官方更新的独立备份

preview.12 起，稳定的根路径操作锁仍位于 backups/〈根路径指纹〉/operation.lock。active.json 原子选择 generations/〈随机指纹〉/ 下的当前备份状态；没有 active.json 的旧布局继续直接读取。

当客户端版本不同且严格匹配已知原版指纹时，用户明确重新应用才创建新代际。旧目录、manifest、备份和历史代际不移动、不覆盖；新事务与恢复只访问当前代际。未知版本或同版本异常变化不触发此流程，版本更新不会自动沿用旧模块选择。
