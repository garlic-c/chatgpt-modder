# Windows 版如何工作，以及使用前必须了解的风险

适用于 0.1.0-preview.10。Windows 版仍为实验功能，尚未完成普通使用流程的完整验收。用户已报告“应用修改后重启 ChatGPT 没有效果”，目前原因未确认，不能将隔离调试成功等同于日常启动已可用。最新状态见 [已知问题](KNOWN-ISSUES.md) 和 [实测记录](WINDOWS-preview.10.md)。

## 1. 修改发生在哪里

Windows 商店版通常安装在受保护的 WindowsApps 目录。修改器通过当前用户的 Get-AppxPackage 和包清单寻找主程序，读取客户端产品、版本、ASAR 资源及 PE 完整性声明。发现安装目录只表示找到了客户端，并不表示该版本可以修改。

匹配已知适配器后，修改器为商店安装创建独立、可写的用户目录副本。补丁写入副本，官方 WindowsApps 安装不变。当前实现不会接管所有权、改写官方目录 ACL，或关闭系统保护。

~~~mermaid
flowchart TD
    A[官方 WindowsApps 安装] -->|只读发现、版本和指纹检查| B{已知适配器匹配?}
    B -->|否| C[仅诊断，禁止修改]
    B -->|是| D[创建用户目录副本并核对复制一致性]
    D --> E[备份副本原版]
    E --> F[在暂存目录修改 ASAR 和 PE 内部完整性声明]
    F --> G[验证并事务替换副本]
    G --> H[桌面 ChatGPT（Modder）快捷方式]
    A --> I[原官方快捷方式仍启动官方版]
~~~

副本按来源安装路径与原 ASAR 指纹分目录，来源记录保存于旁边的 origin.json；官方新版本使用新的来源目录。副本内的 MSIX 描述文件会被移除，副本不会注册成官方商店包。

通常位置如下，实际以 Electron 的 userData 和桌面目录为准：

| 内容 | 位置 | 用途 |
| --- | --- | --- |
| 修改后的副本 | %APPDATA%/ChatGPT Modder/clients/〈来源指纹〉/client | 实际运行补丁的客户端 |
| 来源记录 | 上述 client 的相邻 origin.json | 识别对应的官方来源与原 ASAR 指纹 |
| 副本备份与事务记录 | %APPDATA%/ChatGPT Modder/backups/〈目标路径指纹〉/ | 恢复副本及中断事务 |
| 启动入口 | 桌面 ChatGPT（Modder）.lnk | 指向副本中的主程序 |

本说明描述商店副本流程。引擎仍可能对用户手动选择且通过检查的普通可写安装目录进行原地修改；不能把“官方 WindowsApps 不变”理解成任意所选目录都会额外复制。

## 2. 补丁改变了什么

额度模块修改副本 app.asar 内已锁定版本和 SHA256 指纹的 UI 资源，将额度组件放到头像上方。它读取客户端已有账号身份和额度状态，沿用宿主查询/推送与刷新机制，不绕过登录、不增加额度，也不证明显示值始终是服务器最新值。离线、错误或身份不匹配时使用占位；到达重置时间请求刷新，不自行认定额度恢复。

更改 ASAR 后，修改器更新副本 PE 可执行文件中的 Electron ASAR 头哈希声明，使其与新归档一致，再验证两者相等。这是客户端内部的归档一致性检查，**不是 OpenAI 官方签名或可信发布认证**。原有 Authenticode 签名可能失效，不能再把修改后的 EXE 当作官方签名原件。Windows 路径没有替用户取得官方代码签名。

修改器仅加载随项目发布的内置模块，不提供任意外部脚本入口。补丁安装在客户端副本中，关闭修改器后仍可工作；修改器本身不提供托盘、开机启动或后台服务。

## 3. 为什么“应用成功”后可能看不到效果

应用成功表示文件事务完成，并不表示当前打开的窗口来自该副本。

- 原来的桌面图标、开始菜单、任务栏固定图标及部分协议链接仍可能启动官方安装。当前代码不会替换这些入口。
- 需要从桌面“ChatGPT（Modder）”启动已修改副本。确认运行中的主程序路径位于对应 clients 目录；不要仅凭窗口名称或图标判断。
- 客户端可能仍有托盘或辅助进程，关闭窗口不一定完全退出。引擎会拒绝修改检测到仍在运行的目标。
- 官方实例与副本的单实例行为、默认配置目录、包身份和协议回调可能互相影响。普通快捷方式不附加调试时使用的独立配置目录选项。
- “已定位”“补丁已写入”“成功启动副本”“成功登录”“额度可见”是不同的验收阶段，不能互相替代。

当前用户“重启后没有效果”的反馈仍开放。只读检查已确认其生成的副本存在补丁、PE/ASAR 声明一致、Modder 快捷方式指向副本；尚未确认该次实际启动的程序路径，**不能断言用户选错入口，也不能宣称问题已经解决**。

## 4. 主要风险和边界

| 风险 | 对使用者意味着什么 |
| --- | --- |
| 修改第三方客户端代码 | 源码、构建来源和修改器发行方成为新的信任边界；哈希校验不等于代码绝对安全或官方支持。 |
| 签名、包身份与系统集成 | 副本不是官方 MSIX 安装，签名可信度、通知、协议、浏览器登录回调、权限或其他包依赖可能不同，甚至无法启动。 |
| 登录和账号数据 | 不自动复制凭据、Cookie、聊天数据库或整份配置；可能需要重新登录。默认副本是否复用现有资料目录没有完整验证，不能承诺登录隔离或无缝继承；不要手动链接共享配置目录。 |
| 多实例与并发资料访问 | 如果官方实例和副本碰巧共用资料路径，并发写入可能造成状态冲突或资料损坏；现有“目标程序停止”检查不能证明所有共享资料使用者都已退出。 |
| 安全更新与版本过时 | 官方商店更新不会自动更新独立副本。旧副本可能继续运行已过时的代码；需人工确认新官方版本、重新适配并准备新副本，不能长期忽略更新。 |
| 升级和恢复限制 | 已升级或被其他工具更改的客户端不能强套旧补丁或旧备份。恢复仅恢复已管理副本的程序文件，不是账号资料恢复、官方商店回滚或卸载工具。 |
| 中断、空间与磁盘故障 | 副本、备份、暂存和旧目录可能同时存在，需预留数倍安装体积的空间。复制验证、事务和回滚降低失败影响，但不能保证抵御硬件损坏；旧副本和备份暂不自动清理。 |
| 显示值和版本锚点 | 额度可能延迟或不可用；不应作为计费承诺。压缩变量名、组件和资源随版本变化，未知版本必须停止修改。 |
| 官方支持、条款和分发 | 修改后的客户端不属于官方支持或背书；应自行确认适用条款。只发布修改器和原创补丁，不上传或分发官方客户端副本。 |
| 预览版发行 | 当前修改器未配置公开发行代码签名，完整 Windows 流程尚未验收。不要以关闭安全软件、降低系统保护或忽略安全拦截作为安装步骤。 |

## 5. 隔离调试的成功不能替代普通启动验收

本轮已验证：26.1027.30824 的完整资源指纹、真实独立副本的应用/重复应用/原样恢复/重新启用，以及用户手动登录后的真实额度显示、头像对齐、侧栏切换和主题 CSS 样式。

这些登录和显示结果来自工作区中的独立调试副本，使用客户端支持的新建配置目录。普通桌面快捷方式仅指向正式用户目录副本，没有复制该测试配置，也没有设置相同的配置目录环境。因此测试实例成功不保证普通快捷方式、默认资料目录或重启后的行为相同。用户后续“无效果”的反馈应优先继续调查。

尚未全面验证：普通快捷方式端到端重启、全部登录回调、真实切号/休眠唤醒、持久主题设置、商店升级后的维护及所有系统集成。适配器仍标记 experimental。

## 6. 诊断与退出使用

出现问题时先停止再次应用，记录修改器版本、官方包/客户端版本、所用入口、实际运行程序路径和准确错误。可以导出安装兼容诊断；诊断可能包含本机路径、包身份和文件哈希，分享前审阅，不附凭据、Cookie、聊天内容或完整配置目录。

需要撤销时，先完全退出目标副本，再使用“恢复原版”。引擎会验证当前文件与备份，失败时保留证据，不要手工覆盖官方安装或删除仍需恢复的事务目录。原官方入口仍对应官方安装，但本轮没有完成所有快捷方式和协议场景的验收。

不再使用副本时应确认其进程已退出，并审阅副本、启动快捷方式和备份再清理。当前没有自动卸载/清理旧版本的功能。不要把删除副本程序目录当作删除登录资料，也不要将“恢复原版”当作清除账号数据。

调试端口只能用于明确授权的本机测试，验证结束后关闭；不要带着调试端口长期登录使用。diagnostics、备份和测试配置不进入 Git 或源码包，但 .gitignore 不提供加密或访问保护；测试登录后相关目录可能含敏感数据，禁止整目录上传。
